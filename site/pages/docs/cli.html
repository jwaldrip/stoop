Commands

CommandWhat it does
stoop run [options] -- <command> [args...]Skip the command if a proof matches; otherwise run it traced and record a proof if it passes. The default, so stoop -- make test works too.
stoop explain [options] -- <command> [args...]Say what would happen and why, without launching the command. Checks local proofs only and prints what differed; configured probes can run.
stoop sh <script> [args...]Shell mode for CI. Runs the script with bash --noprofile --norc -eo pipefail, keyed by the script's contents and arguments, GITHUB_WORKFLOW, GITHUB_JOB and the working directory. Made for shell: stoop sh {0}.
stoop ls [--store DIR]List keys, working directories, recorded platforms, proof count, inputs in the newest proof, and when it was created (Unix seconds). Older proofs without platform information are shown as unknown. Each proof also lists the environment variables it leaves out as ignores, and learned exclusions are listed as volatile lines. Readable suite lines show the suite ID, working directory, status, platform, unit count and proven count.
stoop forget <key> [--store DIR]Drop every proof for a key.
stoop forget --volatile <key> [--store DIR]Forget what was learned about environment variables for a key. They count again until they are learned once more. See variables that change on every run.
stoop forget --units [--store DIR] <suite-id>Remove a suite bundle and its lock without deleting the whole-command proof.
stoop pull [--sync git[:remote]]Fetch every published proof from the remote once. Use it at the start of a job.
stoop prune [--sync git[:remote]] [--max-age DUR]Delete published proofs older than --max-age (default 7d). Needs write access.
stoop --help, stoop --versionHelp text and version.

The store root, including an implicit .stoop directory, is trusted and must not be replaced while stoop runs. On Unix, suite files under units/v1 are opened relative to the store root and never follow a link below it. On Windows, stoop checks some suite paths for links and reparse points, but the checks are path-based and not atomic: a directory replaced by a junction after a check is still followed.

On a traced stoop run, recognized test, lint and build launches can produce one diagnostic line, for example stoop: observed jest via npm (diagnostic only). The original command still runs unchanged; the observation is not saved in its proof. Warm skips, --quiet, --no-record, stoop sh and stoop explain omit the line.

Observation stops at 1,024 captured execs, 1,024 tracked tasks or 1,024 pending child stops, or if an exec has more than 128 arguments or 16 KiB of arguments. Runners observed before a limit can still be reported; the command continues unchanged.

Changed-unit hook

Write '{changed}' where a test command takes test files, and say which files are tests: stoop run -- npx jest '{changed:*.test.ts}'. The filter is a list of patterns separated by |, with ! to exclude. Always single-quote the placeholder. Unquoted, bash and zsh expand commas and wildcards before stoop sees them, and fish refuses the wildcard.

On Linux x86-64 and arm64, a changed run of a recorded suite is an attribution pass when every condition below holds. Otherwise the full form runs, as before. The placeholders must be single-unit forms: not {changed-inputs}, and not a list form (:file or :nul) with a :comma, :space or :newline join. A unit whose text holds the separator of a joined placeholder also keeps the full form, and so does a :file list whose unit's absolute path (:abs) holds a newline. Shell code that reads $STOOP_CHANGED_INPUTS or $STOOP_CHANGED_INPUTS_FILE keeps the full form, as {changed-inputs} does; other shell environment code needs no placeholder. The run must be an ordinary recorded run: not --no-record, --allow-network, --probe, --ignore or --ignore-env, not explain, not forced to the full form (for example by STOOP_FULL), and not independent = false. A recorded proof for the command must exist and must not match the current tree. CI must not be set, and the suite must not be disabled by enabled = false. The roster must have no unit proof, and the suite must not be disabled (see below). The pass launches the command once for each unit, in catalog order, with the unit in place of each placeholder, and traces each launch. The pass stops at the first launch that breaks an independence check (see below). Each launch sets STOOP_CHANGED and STOOP_UNITS to its unit, and STOOP_CHANGED_FILE to a newline list that names only that unit. STOOP_CHANGED_INPUTS is empty, and STOOP_CHANGED_INPUTS_FILE names an empty file. Those two files sit in a folder that only that launch uses, with mode 0700, and the folder is removed when the launch returns. A list form is the path of its list file: {changed:nul} names a NUL-separated list, and @{changed:file} passes @ followed by that path. A list file is never an input or an output of the unit. A launch that exits 0 and reads its own unit file stores that unit's proof. A launch that exits otherwise stores none, and the run goes on. The run exits with the first nonzero launch status in catalog order. With no failing launch, a run exits 125, which means it has no verdict, when a unit could not be launched or the run stopped before its last launch; otherwise it exits 0. Each unit is one traced launch, so a pass costs more than the full run it replaces.

After a pass stores unit proofs, later changed runs take the full form until the unit proofs are cleared, for example by stoop forget --units. A launch that breaks an independence check stops the pass and disables the suite. Three breaches count: a launch reads a file that another unit of the roster owns; a launch writes a unit's own file, or a path that another unit's proof names as an input or as an output; a launch exits 0 without reading its own unit file. The run prints stoop: suite {id} disabled: {breach}; run 'stoop forget --units {id}' after fixing it, and the suite is stored as disabled. Its changed runs take the full form, with nothing new printed, until stoop forget --units clears the state. A roster change does not clear it. A pass whose unit proofs exceed 8 MiB disables the suite the same way, and keeps no unit proof. A launch that fails keeps its own status, which the run reports ahead of 125. The run after a pass takes the full form even when nothing changed, and records a whole-command proof; an unchanged tree skips only through that proof. When the full command runs, stoop prints the words it removed. A declared option uses its declared arity; an undeclared option immediately before a standalone placeholder follows the v0.2.0 rule.

The placeholder assumes two things about the command: each test file passes alone exactly as it does in the full suite, and running the command with no test files does nothing beyond running them all. Stoop cannot check either premise.

On Linux and macOS, stoop explain -- npx jest '{changed:*.test.ts}' counts the regular files selected by the filter under the selected root. That count is the stoop: tracked N units; filter '...' line. It is a current catalog count, not a count of saved unit proofs. The inline filter overrides a matching suite's units array. An exclusion-only inline filter narrows that configured array. Two different argv filters in one command are refused.

On Linux x86-64 and arm64, explain of a suite with a filter prints two more lines after its decision, unless explain answers an expanded or ambiguous placeholder with its own line. The first is stoop: tracked {n} units, {m} inputs; {p} proven, {q} without a proof (suite {id}), and it counts saved unit proofs. n is the roster size, m the distinct inputs that the roster's unit proofs name, p the roster units that hold a unit proof in a current bundle for this command, and q the rest. A disabled suite counts no proofs. The second line says what the next changed run does. stoop: would run an attribution pass: {n} launches means that run launches each unit once. stoop: no attribution pass: {reason} means that run starts no pass: it skips when the whole command's proof still holds, and it runs the full command for every other reason. For a suite that a breach disabled, the reason names the suite, the breach and the command that clears it. A store that cannot take a new entry gets its own reason. Explain reads the store and never takes the suite lock, so it cannot see a run that holds the lock. That run prints its busy line and runs the full command.

When the residue of a suite's whole-command proof is known and not empty, explain prints one line before the tracked line: stoop: the full command reads {k} files no unit's own run reads, such as {p1}, {p2}, {p3}, {p4}, {p5}; widen the filter or narrow the command. The residue is the set of input paths that the whole command reads and that no unit's run reads, for example a lint script, or a program that only the full command runs. It is compared by path. The line names the first five paths in sorted order and counts every path. Nothing skips on the residue in this release: runs print nothing new, and the residue appears only in explain.

Patterns match root-relative UTF-8 paths, case-sensitively and byte by byte. Separate patterns with |; a leading ! excludes and the last matching pattern wins. * and ? stay within a path component, ** can cross directories, and [a-z] matches a byte in a range. A pattern with a slash is rooted; a name without one matches at any depth. A trailing slash selects directories only. Backslash escapes the next character.

Filters inside shell code are not supported. A shell operand is an environment-form hook: its words stay as written, and each launch exports its values to the environment. Explain does not extract filters from shell code. Put the filter in a separate quoted argv placeholder, for example '{changed:/foo}' for the top-level file foo, or configure the suite's units array.

The catalog skips symlinks, .git, .stoop, and .stoopignore matches. In a Git worktree with Git available, it also excludes Git-ignored untracked paths while retaining tracked files. Without Git it walks without Git's ignore rules. If Git's inventory fails or disagrees, or the catalog exceeds 4,096 units or 65,536 directories, explain reports an unknown universe. On Windows the universe is unknown. Discovery does not run the test command or save per-unit proofs.

Each stoop explain recomputes the catalog. Directory listings alone cannot validate it: a file can become a symlink without changing its name, and ignore rules or Git state can change eligibility without changing listings. Stoop does not cache or reuse this catalog across invocations.

Discovery reports an unknown universe if a filter exceeds 32,768 bytes or 1,024 patterns, contains an empty character class, or exceeds 8,388,608 matcher state updates across the scan. The root .stoopignore must be a regular file of at most 1 MiB; a symlink, special file, unreadable file, or larger file makes the universe unknown. These limits do not alter the hook's full-command form.

Stoop detects common quoting mistakes and exits 2 before anything runs: a comma inside braces, a | or ; outside quotes, a cut-off placeholder, a brace-expanded word such as changed:*.t, or a placeholder in shell code or a shell command's $0. An undeclared option with an ambiguous value extent is refused. Attach the placeholder, put it immediately after its option or after --, or declare the option in .stoop.toml.

On the first run of a placeholder argv, stoop records that argv before running it, whatever the result. The record is not a proof and never causes a skip. If a later invocation has the placeholder removed or emptied, stoop recovers its full form only when the recorded form and configuration still agree. Changed configuration and conflicting configured forms are refused with exit 2. To refresh a stale record after changing configuration, run the same command again with the placeholder quoted. Multiple unconfigured legacy matches run as typed without a skip.

Quoting

Each row is what the shell does before stoop starts. Stoop's Linux CI covers every row.

Shell or contextWriteWhat stoop receives
bash, dash, zsh, fish'{changed:*.t}'The placeholder, unchanged.
bash, dash, zsh, fish'$STOOP_CHANGED'The environment spelling, unchanged, with the same filters.
zsh, fish{changed:*.t}, unquotedNothing: the shell refuses the wildcard before stoop starts.
bash{changed:*.t,*.u}, unquotedBrace expansion splits it into words without braces; stoop refuses that shape before it launches anything.
dash{changed:*.t|*.u}, unquotedThe pipe splits the command; stoop receives a cut-off word and refuses it.

GitHub Actions run:'{changed:*.t}' or '$STOOP_CHANGED'The placeholder or environment spelling, unchanged, under the step's bash.

Hook configuration

An optional .stoop.toml at the selected root configures explicit hooks. Plain commands do not read it. Unknown or duplicate keys, invalid values, or multiple matching suites produce one warning with a location. Stoop ignores the configuration for that invocation and runs the full hook command without a proof skip. An ambiguous option still needs a valid declaration or an unambiguous argv.

Configuration and GitHub event inputs used by a hook must be regular files no larger than 8 MiB. Unreadable, oversized, or nonregular inputs prevent a proof skip.

[units]
default_branch = "main"
verify_every = 20

[[units.suite]]
id = "tests"
cwd = "."
match = ["./test", "--files", "base", "more", "{changed}"]
options = [{ names = ["--files", "-f"], values = "many" }]

A suite's required id is unique, and its nonempty match array matches the typed argv exactly. A token * matches one argument. Placeholder aliases normalize to the same spelling, but filters and modifiers remain part of the match. cwd is root-relative, with . for the root; omitting it matches any directory.

Each option declaration lists aliases and uses values = 0, 1, or "many". Declarations match exact option words and long --name=value forms. Attached short values or partial placeholder values touching a declared name are refused. Without a declaration, the v0.2.0 adjacent-option and attached-carrier rules remain, and ambiguous value extents refuse with exit 2. After -- all words are positional. Zero leaves a following placeholder positional; one consumes one value; many consumes values through the next option or --. Repeated aliases of a selected declared option are removed too.

For a declared many option, -foo{changed} tail and --files=base{changed} tail are refused. Without a declaration, those forms keep their v0.2.0 behavior.

Two delimiter cases changed from v0.2.0 to preserve positional words. ./runner --files '{changed}' -- --files positional now runs ./runner -- --files positional instead of ./runner. ./runner -- --files '{changed}' now runs ./runner -- --files instead of ./runner.

The accepted suite keys also include enabled, independent, and a units pattern array. independent = false runs the full hook even when a whole-command proof matches. The global enabled setting and a suite's enabled setting turn off attribution passes. Runner tables, templates, and job counts are not supported yet.

Hooked commands run fully on a default-branch push, an explicitly enabled sync writer, and every verify_everyth positive run ordinal. Missing or invalid ordinals force a full run when sampling is configured. GitHub uses its event payload and push ref; a pull request merge ref is not a default-branch push. Unavailable or conflicting CI branch context forces a full run. Branch data never grants permission to publish proofs.

Options

Options go before --. Everything after it is the command.

--key NAME
Name the proof yourself. The default is the program name plus a hash of the arguments and the working directory, like cargo-46fcb2881638d3cc. A named proof must still match the working directory and repository identity.
--root DIR
The repository root. Defaults to the nearest directory containing a .git directory or file; a nested repository uses the inner root. Without .git, the working directory is the root. Paths inside the root are stored relative to it, and only reads inside it can be recorded as absent.
--store DIR
Where proofs live. Defaults to <root>/.stoop, or $STOOP_STORE. An external store scopes automatic keys by Git origin, or by the physical root path if there is no origin. See keys.
--env NAME
Count this variable too. The environment already counts, minus runner bookkeeping (GITHUB_, RUNNER_, ACTIONS_, INPUT_, STOOP_) and the curated per-run variables; use this to put one back. A name the command text mentions counts anyway. The command text is the argv words and the stoop sh step body, not the files the command runs. Repeatable.
--ignore-env NAME
Exempt a variable that changes without mattering, such as a per-run token. An exempt name is never counted, even when it was learned. Repeatable.
--no-learn-volatile
Do not learn variables that change on every run. The curated list still applies. See variables that change on every run.
--probe CMD
External state to verify. CMD runs with sh -c before the command; its output is hashed into the proof and must match again for a skip. A probe that fails, or prints something different after the command finishes, means nothing is recorded. Declaring a probe accepts network use for that step. Repeatable.
--allow-network
Record runs that used the network anyway. You are vouching that the network can't change the result.
--max-age DUR
A proof stops counting after DUR: 90s, 30m, 12h, 7d, or a bare number of seconds. Default 7d; 0 means never expire.
--ignore PATTERN
Paths whose reads don't count. Same syntax as .stoopignore. Repeatable.
--no-record
Check and skip as usual, but never write a proof. For jobs you don't trust.
--allow-id-token
Permit the OIDC request variable names listed in STOOP_PASS_ENV to reach this command. Such a command runs untraced, without running probes or using or writing proofs; in shell mode it blocks job attestation.
--literal
Treat a {changed} placeholder as ordinary text. Turns off every hook rule for this invocation, including the empty-value hint. Use it when a literal brace argument is what you mean.
--sync git[:REMOTE]
On a run miss, fetch this key's proofs from refs/stoop/<key> on the git remote (default origin) and check again. Explain checks local proofs without fetching. See git sync.
--sync-write
Publish proofs to that remote after a recorded run. Off by default; use it on the default branch only.
--quiet
Print nothing about the decision. The command's own output is untouched.

Environment

STOOP_RUN_NUMBERPositive ordinal used for verify_every. If absent on GitHub, GITHUB_RUN_NUMBER is used.

STOOP_OFF=1Don't trace or skip; run commands directly.
STOOP_DTRACE_DIAGNOSTIC=1macOS only, with passwordless sudo: run the command once under DTrace and print a report. Never recorded. list adds the paths and the process tree; raw adds every line the tracer printed.
STOOP_STORE=DIRDefault for --store.
STOOP_SYNC=git[:REMOTE]Default for --sync.
STOOP_SYNC_WRITE=1Same as --sync-write.
STOOP_PASS_ENVComma- or whitespace-separated names selected from ACTIONS_ID_TOKEN_REQUEST_URL and ACTIONS_ID_TOKEN_REQUEST_TOKEN. Each listed name requires --allow-id-token. See CI recipes.
STOOP_ENV_SALTA secret that keys the environment hashes stored in proofs. Set it from a repository secret wherever proofs are published. See How git sync works.
STOOP_LEARN_VOLATILE=0Same as --no-learn-volatile. Empty, 0, false, no and off turn learning off.

These are switches. A variable that is empty, or set to 0, false, no or off, is off; anything else is on. That makes the common CI idiom STOOP_SYNC_WRITE: ${{ github.ref == 'refs/heads/main' && '1' || '' }} safe: the empty string on a pull request does not turn publishing on. An empty STOOP_SYNC or STOOP_STORE counts as unset.

Exit codes

CommandExit code
run, sh0 on a skip; otherwise the command's own code (128 + signal if it was killed). 127 if it couldn't be started.
explain0 if the command would be skipped, 1 if it would run.
forget0 if proofs were dropped, 1 if there were none for the key.
prune0 on success, 1 if the remote refused.
Any2 for a usage error, such as an unknown option.

What the messages mean

stoop: skip KEY: N inputs unchanged since T ago (Xms)
A proof matched. The command did not run.
stoop: run KEY: REASON
No proof matched. REASON is what differed from the newest one: no proof yet, src/main.rs changed, env changed, proof expired, STOOP_FULL is set.
stoop: recorded N inputs for KEY
The run passed and a proof was written.
stoop: not recorded: REASON
The run passed but couldn't be vouched for. See when it runs anyway.
stoop: not recorded: KEY changed while the command ran
An eligible input's first observed identity differs from its exit state. The command keeps its exit status and no proof is saved. A timestamp, xattr or bind-alias change made by the command can make stoop refuse to record. See the coverage limits.
stoop: debug: not compared KEY: REASON
With STOOP_DEBUG, an input comparison was skipped because its observation, physical route or write footprint could not support it.
